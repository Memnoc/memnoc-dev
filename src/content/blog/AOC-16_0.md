After all, not using AI these days it's like trying to outrun a motorbike because we used to run with out legs and that's what we liked, damn motorbikes stealing our jobs!! 🙄

Ok enough chit-chat, here's what's gonna happen: I am gonna set you up with an easy local development environment to get you started.

## Local set up

1. First, you need `npm` or `pnpm` or `bun` or whatever you like. Since `npm` is the first thing that came to mind and very commonly used, let's use that.

`npm --version` -> to see which version you have, if you have it. If not, use your brain and Google to find out how to install it on your machine/OS.

You also need `Node`:

`node --version` -> install if you don't have it

2. Go or create a folder for your projects. Mines live in `~/Code` and if you don't know `~` is the sign for `$HOME`. My folder is called `AOC-TS` to make sure I remember a few hours from now what the heck that folder is about. Call yours what you like.

`cd` into this folder, and run:
`npm init -y` -> it will create a `package.json` and the `-y` will say yes to all the questions that command would normally ask with a **yes** or a **no**

3. **Install the development tools**
   In the same folder, run:

   ```
   npm install -D typescript @types/node tsx vitest eslint @eslint/js typescript-eslint
   ```

   The `-D` flag records these packages under `devDependencies`:

   | Package             | Purpose                                          |
   | ------------------- | ------------------------------------------------ |
   | `typescript`        | Checks TypeScript types                          |
   | `@types/node`       | Provides type definitions for Node.js APIs       |
   | `tsx`               | Runs TypeScript files                            |
   | `vitest`            | Runs automated tests                             |
   | `eslint`            | Checks code against lint rules                   |
   | `@eslint/js`        | Provides standard JavaScript lint configurations |
   | `typescript-eslint` | Adds TypeScript support and lint rules           |

4. Lastly, set up version control:
   You can use a tool I have created called ![Gig](https://github.com/Memnoc/gig). You don't have to install it, just run it via `npx`:
   `npx gig-ignite list` -> and in the list, chose Typescript. The tool will create a complete `.gitignore` for your project.

If you want to do it by hand, while in the root of your project (this means while inside the main folder):
`touch .gitignore` and add, at the very minimum:

```
/node_modules
/coverage
/dist

```

We want to keep `package.json` and `package-lock.json` as version-controlled files, so anyone (including you in a couple of months or years) who uses the project have the right dependencies.

5. **Configure TypeScript**

We create `tsconfig.json` with `touch tsconfig.json` and we fill it with:

```
{
"compilerOptions": {
"target": "ES2023",
"module": "NodeNext",
"strict": true,
"noUncheckedIndexedAccess": true,
"noEmit": true,
"types": ["node"]
},
"include": ["src/**/*.ts"]
}

```

This sets up strict type checking for our source files, accounts for potentially missing indexed values, and disables generated JavaScript output. [TypeScript configuration reference (https://www.typescriptlang.org/tsconfig/)](https://www.typescriptlang.org/tsconfig/)

6. **Ran our first program**

Create a file `hello.ts` inside `src/hello.ts`:

Fill the file with this code:

```typescript
const message: string = "Ready for Advent of Code!";
console.log(message);
```

Then run:

```

npx tsx src/hello.ts
npx tsc

```

If you did everything correctly, the first command prints "Ready for Advent of Code" and the second completed without errors, confirming that the program passed type checking.
