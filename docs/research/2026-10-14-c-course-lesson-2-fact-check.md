# Codex research notes - C course Lesson 2 fact check

Prepared by Codex for author review. Checked 2026-10-14 against public WG14 drafts and official GCC/GNU C Library documentation. Scope: `src/content/blog/Let's_learn_C_(NO_AI)_2.md`. Recommendations below preserve the converter examples while correcting their explanations.

1. **Type and storage.** Describe a variable here as a named object whose type determines its permitted values and operations. Storage duration determines lifetime; it is distinct from type. The converter's ordinary local objects have automatic storage duration. Avoid suggesting C permits arbitrary manipulation without constraints. Evidence: [N1570](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1570.pdf), sections 3.15, 6.2.4, 6.2.5.

2. **Portable ranges.** Replace the questionable K&R quotation with a paraphrase. Exact sizes/ranges are implementation-dependent. `sizeof(char)` is one C byte, containing `CHAR_BIT` bits, at least eight. C11 guarantees `short` and `int` cover at least -32767 through 32767, and `long` at least -2147483647 through 2147483647; typical widths are examples, not guarantees. Floating precision differs from range: `FLT_DIG >= 6`, `DBL_DIG >= 10`; `float` need not occupy 32 bits. C23 requires two's complement signed representation. Evidence: [N1570](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1570.pdf), sections 5.2.4.2.1, 5.2.4.2.2, 6.5.3.4; [GCC integers](https://gcc.gnu.org/onlinedocs/gcc/Integers-implementation.html).

3. **Formats depend on the function.** Label the list specifically for `printf`: `%c` expects `int` and prints a character; `%d` expects `int`; `%f` expects `double`. Ordinary `char` arguments undergo integer promotions, usually to `int`; `float` promotes to `double`. Evidence: [N1570](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1570.pdf), sections 6.3.1.1, 6.5.2.2, 7.21.6.1; [GNU character conversions](https://sourceware.org/glibc/manual/latest/html_node/Other-Output-Conversions.html), [integer conversions](https://sourceware.org/glibc/manual/latest/html_node/Integer-Conversions.html), [floating conversions](https://sourceware.org/glibc/manual/latest/html_node/Floating_002dPoint-Conversions.html). For `scanf`, `%f` requires `float *`, `%lf` requires `double *`; pointer arguments do not receive the float-to-double promotion. Evidence: [GNU numeric input](https://sourceware.org/glibc/manual/latest/html_node/Numeric-Input-Conversions.html); N1570 section 7.21.6.2.

4. **Statements and expressions.** An expression can compute a value, designate an object/function, or produce side effects. `x = a + b * 2` is an assignment expression with a value; adding `;` makes an expression statement and discards that value. Blocks and `while (...) { ... }` are statements without a final semicolon. Declarations are a separate grammatical category. Evidence: [N3096](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf), sections 6.5, 6.5.16, 6.8.2, 6.8.3, 6.8.5.

5. **Grouping and sequencing.** Explain precedence and associativity as rules for grouping operators, not a general execution order. `a + b * 2` groups as `a + (b * 2)`; the grouping does not establish a general left-to-right order of operand evaluation. Evidence: [N3096](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf), section 6.5 paragraph 3 and footnotes 96-97.

6. **Integer converter.** Since C99, integer division truncates toward zero: `5 * (0 - 32) / 9` yields -17. Correct the first output's `03000` and prose's positive `17`. `5 / 9 * (fahr - 32)` yields zero because its integer division yields zero first. K&R-era negative division rules differed; do not present them as current rules. Evidence: [N1256](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1256.pdf), section 6.5.5 paragraph 6; [GCC integers](https://gcc.gnu.org/onlinedocs/gcc/Integers-implementation.html) documents C90's latitude and GCC's truncation toward zero.

7. **Floating converter.** The existing expression works with `float fahr`: usual arithmetic conversions make its arithmetic floating-point. Assignment to a floating destination alone would not repair integer-only `5 / 9`. Explicit `5.0f * (fahr - 32.0f) / 9.0f` makes intent visible. Floating arithmetic approximates results; formatted rounding does not improve stored accuracy. Evidence: [N1256](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1256.pdf), sections 6.3.1.8, 6.5.5; [GNU floating conversions](https://sourceware.org/glibc/manual/latest/html_node/Floating_002dPoint-Conversions.html).

8. **Header, entry point, assignment.** `#include <stdio.h>` makes the input/output header's declarations, types and macros available, including `printf`; it does not include the whole standard library. `int main(void)` has no parameters. Before C23, empty parentheses in a declaration give no parameter information, while an empty-list definition specifies no parameters. C23 makes an empty list equivalent to `(void)`. `lower = 0;` after declaration is assignment; `int lower = 0;` is initialization. Evidence: [N1256](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1256.pdf), sections 6.7.5.3 paragraphs 10/14, 6.7.8, 7.19; [N3096](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3096.pdf), sections 5.1.2.2.1, 6.7.6.3 paragraph 13, 6.10.2.

9. **Display.** In `%3.0fF\t%6.1fC\n`, 3 and 6 are minimum widths, `.0` and `.1` select fractional digits, and `F`/`C` print literally. Regenerate the final output with suffixes and padding. `\t` is a horizontal tab whose appearance depends on the terminal. Evidence: [GNU output syntax](https://sourceware.org/glibc/manual/latest/html_node/Output-Conversion-Syntax.html), [floating conversions](https://sourceware.org/glibc/manual/latest/html_node/Floating_002dPoint-Conversions.html); N1570 sections 5.2.2 and 7.21.6.1.

Suggested compact SOURCES banner: WG14 N1570 - language rules; GNU formatted output - examples; GCC C dialect options - choose `-std=c11` explicitly for reproducible compilation. [GCC dialect documentation](https://gcc.gnu.org/onlinedocs/gcc/C-Dialect-Options.html) defines supported standards and explains the default dialect.
